# ADR-003: Bun workspaces + Turborepo with the runner at root and `web/` as a sibling

## Status

Accepted

## Date

2026-05-31

## Context

ADR-002 decided to convert the repository into a Turborepo-managed monorepo
with the runner and the web UI as sibling packages. This ADR fixes the concrete
tooling and layout. The runner currently uses Bun as runtime, test runner, and
bundler, with its `package.json`, `src/`, and `bin` at the repository root. The
web UI must be a separate root-level package and must not move into `src/`.

## Decision

Use **Bun workspaces** as the package manager with **Turborepo** orchestrating
tasks. Keep the runner package in place at the repository root (its `src/`,
`package.json`, scripts, and `bin` are unchanged) and make that root
`package.json` the workspace root with `"workspaces": ["web"]`. Add the web UI
as a new `web/` package. A root `turbo.json` defines the shared `build`,
`dev`, `typecheck`, and `test` pipelines that fan out to both packages.

## Alternatives Considered

### Alternative 1: pnpm workspaces

- **Description**: pnpm as package manager, the most common Turborepo pairing.
- **Pros**: Largest body of Turborepo/React docs; strict node_modules.
- **Cons**: Introduces a second package manager alongside Bun; the runner's
  install/link flow would move off Bun.
- **Why rejected**: Keeping a single Bun toolchain is simpler and matches the
  existing repo; Turborepo supports Bun workspaces.

### Alternative 2: Restructure runner into `apps/runner`

- **Description**: Make the root workspace-only and move the runner under
  `apps/`.
- **Pros**: Symmetric `apps/*` layout.
- **Cons**: Rewrites every runner path, script, and `bin` reference for no
  functional gain; high disruption.
- **Why rejected**: YAGNI; ADR-002 explicitly aims to preserve the runner's
  current commands.

## Consequences

### Positive

- Single Bun toolchain across the repo; runner commands unchanged.
- Web app added with minimal disruption; room to add more workspaces later.

### Negative

- The root `package.json` is both a package (the runner) and the workspace
  root — a mixed role, though fully supported by Bun + Turborepo.

### Risks

- Turborepo + Bun workspaces is less documented than pnpm. *Mitigation*:
  pipelines are simple (build/dev/typecheck/test); validate during setup.

## Implementation Notes

Web package name: `@workflow-runner/web`. Root scripts delegate to `turbo run`.
The runner's existing `bun test`, `tsc`, and `bun build` scripts are wired in as
its package tasks.
