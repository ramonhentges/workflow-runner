# ADR-003: Run-aware deletion — block while running, plain confirm otherwise

## Status

Accepted

## Date

2026-06-03

## Context

Workflows can be deleted from the web app, but a workflow may be referenced by a
live run in progress or by finished runs in history. Deleting the file mid-run
risks confusing or breaking an active run; deleting a workflow with only
finished runs is harmless to those runs (their recorded history is independent
of the file). We need a deletion policy that protects active runs without adding
friction for normal cleanup.

## Decision

When a user deletes a workflow:

- **If it has a live run in progress**, refuse the delete with a clear message
  ("stop the active run first"). The same guard applies to rename/identity-
  changing edits.
- **Otherwise**, show a standard delete confirmation and delete. **No special
  "past runs reference this" history warning** is shown — finished-run history
  stands on its own and does not need to gate cleanup.

## Alternatives Considered

### Alternative 1: Block while running, warn on history

- **Description**: Block deletes during an active run and, for finished runs, show an extra warning that past runs reference the workflow.
- **Pros**: Maximizes awareness of provenance links.
- **Cons**: The history warning adds friction for routine cleanup with no real risk, since finished-run history is self-contained.
- **Why rejected**: User chose to drop the history warning as unnecessary noise.

### Alternative 2: Always confirm, never block

- **Description**: A single generic confirmation for any delete regardless of run state.
- **Pros**: Simplest.
- **Cons**: Allows deleting a workflow mid-run.
- **Why rejected**: Does not protect active runs.

### Alternative 3: Hard block if any runs exist

- **Description**: Only allow deleting workflows that have never been run.
- **Pros**: Fully protects provenance.
- **Cons**: Leaves clutter; prevents normal cleanup of completed work.
- **Why rejected**: Too strict for a personal authoring tool.

## Consequences

### Positive

- Active runs are protected; routine cleanup stays frictionless.
- Simple, predictable behavior with a single special case (active run).

### Negative

- A deleted workflow with finished-run history can no longer be re-run or inspected as a file, with only a standard confirm beforehand.

### Risks

- A user could delete a still-useful workflow after its runs finish. Mitigation: the standard confirmation step; duplicate-existing and recreation remain available.

## Implementation Notes

"Live run in progress" is determined from current run state. Finished-run
history is unaffected by deletion and is not consulted as a gate.
