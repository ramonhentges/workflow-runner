# Task 01: Monorepo tooling: Bun workspaces + Turborepo

## Overview
Convert the single-package repository into a Bun-workspaces + Turborepo monorepo with the runner left in place at the root and a `web/` workspace reserved for the new UI. This is the foundation every web task builds on; it must preserve the runner's existing Bun commands unchanged.

- MINIMIZE CODE — show code only to illustrate current structure or problem areas

</critical>

<requirements>
- The root `package.json` MUST become the workspace root via `"workspaces": ["web"]` while remaining the runner package (its existing `bin`, `scripts`, and dependencies unchanged).
- A root `turbo.json` MUST define `build`, `dev`, `typecheck`, and `test` pipelines that fan out to workspaces.
- Root scripts MUST delegate to `turbo run <task>`; the runner's own `bun test`, `tsc --noEmit`, and `bun build` MUST remain runnable and produce identical results.
- A `web/` directory with a minimal placeholder `package.json` (name `@workflow-runner/web`, private) MUST exist so the workspace resolves; full app scaffolding is task_04.
- Turborepo MUST be installed as a dev dependency; `bun install` MUST succeed and link the workspace.
</requirements>

## Subtasks
- [x] 01.1 Add the `workspaces` field to the root `package.json` and a placeholder `web/package.json`.
- [x] 01.2 Author `turbo.json` with build/dev/typecheck/test pipelines and appropriate outputs/cache settings.
- [x] 01.3 Wire the runner's existing scripts as its workspace tasks and add root-level `turbo run` delegating scripts.
- [x] 01.4 Verify `bun install` links the workspace and the runner's `typecheck`/`test`/`build` still pass.
- [x] 01.5 Add a smoke check that `turbo run typecheck` discovers both packages.

## Implementation Details
Modify the root `package.json` per TechSpec "Development Sequencing" step 1 and ADR-003. Keep the runner's `src/`, `bin`, and scripts intact; the root simultaneously acts as a package and the workspace root (supported by Bun + Turborepo). Create `turbo.json` at the root. The `web/` placeholder only needs a valid `package.json` so the workspace glob resolves — Vite/React scaffolding belongs to task_04.
