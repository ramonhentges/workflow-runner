# ADR-002: Live per-IDE discovery of agents and models, with manual override

## Status

Accepted

## Date

2026-06-03

## Context

A step references an `agent` and a `model` whose valid values are defined by the
selected `ide`. The only authoritative source of an IDE's available agents and
models is the running IDE itself — the app already reads them from a live ACP
session (`availableModeIds` in `ide-profiles.ts`). Users want these values
suggested per IDE via endpoints, but must also be able to set them by hand
(e.g. when the IDE is not installed locally, or to use a value not yet
advertised).

## Decision

Provide **per-IDE discovery endpoints that probe the selected IDE on demand** and
return its actual available agents and models, used to populate the step
editor's agent/model pickers. Discovery is **always paired with a manual-entry
override**: if the IDE cannot be reached (not installed, not authenticated,
probe fails) or the user prefers, they can type any agent/model id directly. No
caching layer in this phase — each probe reflects current reality.

## Alternatives Considered

### Alternative 1: Cache after first probe

- **Description**: Probe once, cache the list per IDE, serve from cache with a manual refresh action.
- **Pros**: Faster repeat use; fewer subprocess spawns.
- **Cons**: List can drift until refreshed; adds cache lifecycle and invalidation concerns.
- **Why rejected**: Premature optimization for a local, single-user tool; correctness-first is simpler and good enough now.

### Alternative 2: Manual entry only (no discovery this phase)

- **Description**: User always types agent/model ids by hand; IDE lists serve only as documentation.
- **Pros**: Smallest scope; no subprocess probing.
- **Cons**: Poor discoverability; error-prone ids; fails the stated requirement that agents/models be retrievable by IDE.
- **Why rejected**: Does not satisfy the explicit requirement for per-IDE retrieval endpoints.

## Consequences

### Positive

- Pickers reflect exactly what the selected IDE actually supports.
- Manual override keeps authoring possible even when the IDE is unreachable.
- No cache staleness or invalidation logic to maintain.

### Negative

- Probing spawns/queries a subprocess, so discovery is slower than serving a static list and depends on the IDE being installed and authenticated.

### Risks

- A slow or hanging IDE probe could degrade the picker. Mitigation: graceful fallback to manual entry with a clear message; treat discovery as best-effort, never blocking save.

## Implementation Notes

Discovery is best-effort and must never block authoring or saving. Manual values
are accepted as-is and validated by the existing rule that an unknown ide/agent
fails at the step (fail-at-the-step), not at save time.
