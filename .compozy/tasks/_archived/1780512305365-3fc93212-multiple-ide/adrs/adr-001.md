# ADR-001: Per-step IDE selection with unified full-parity step schema

## Status

Accepted

## Date

2026-06-02

## Context

Today every workflow step runs on opencode: the step's `ide` field exists in the
schema but is ignored, and the agent session hardcodes the opencode subprocess and
opencode-specific agent/model/mode selection. Workflow authors increasingly want to
route different steps to different coding agents (opencode, Claude Code, Codex CLI,
Gemini CLI) to play each agent's strengths, models, and pricing within a single
workflow. All four agents are ACP-compatible as of early 2026, so a single workflow
can in principle drive any of them through the same orchestration loop, but each
agent exposes "agent/persona" and "model" selection differently and there is no
universal mode API.

The decision is how broadly and how uniformly to support multiple IDEs in the first
release.

## Decision

Adopt per-step IDE selection at full parity behind the existing session-factory port.

- Each step declares `ide`, `agent`, `model`, and `mode`. `ide` is **required**.
- The runner reads `ide` from the step and routes to the matching IDE behind the
  existing session-factory boundary; the orchestration loop and MCP handoff/finish
  contract stay IDE-agnostic.
- The first release supports **opencode, Claude Code, Codex CLI, and Gemini CLI**,
  each at full parity: agent/persona selection, model selection, interactive and
  autonomous modes, and handoff/finish all work on every supported IDE.
- A single workflow may freely mix IDEs across steps, including cross-IDE handoffs.
- IDE availability/authentication is validated when execution reaches the step
  (fail-at-the-step), preserving the work of earlier steps.

## Alternatives Considered

### Alternative 1: Phased rollout (opencode + Claude Code first, Codex/Gemini fast-follow)

- **Description**: Same per-step architecture, but ship only the IDEs with the most
  mature ACP bridges first and add the rest later.
- **Pros**: Lower delivery risk; smaller first increment; time to confirm each
  agent's agent/model selection surface.
- **Cons**: Does not deliver the agents the user wants now; fragments the rollout and
  delays mixed-workflow value.
- **Why rejected**: The user explicitly wants opencode, Claude Code, Codex, and
  Gemini available together.

### Alternative 2: One IDE per workflow

- **Description**: Select a single IDE for the entire run rather than per step.
- **Pros**: Simplest routing and adapter logic; one IDE concept per run to validate.
- **Cons**: Contradicts the requirement to read `ide` from each step; blocks
  mixed-agent workflows and cross-IDE handoffs, which are the core value.
- **Why rejected**: Defeats the purpose of the feature.

## Consequences

### Positive

- Workflow authors can route each step to the best-fit agent and mix agents in one
  workflow, including handoffs across IDEs.
- The orchestration loop and MCP contract remain unchanged and IDE-agnostic.
- Existing workflows keep working with a one-time, low-cost edit (they already set
  `ide`).

### Negative

- Each supported IDE needs its own adapter translating the four step fields to that
  agent's native ACP surface; adding an IDE is non-trivial.
- "Full parity" is a standing commitment: every supported IDE must keep up with
  agent/model/mode selection and handoff/finish.

### Risks

- An agent's ACP surface may not expose persona or model selection the same way
  opencode does. Mitigation: per-IDE adapters absorb the differences; if an agent
  genuinely cannot honor a field, that surfaces as a clear step-level error rather
  than silent divergence.
- ACP bridges for some agents may be young and change. Mitigation: pin/document
  required bridge versions; fail-at-the-step gives clear diagnostics.

## Implementation Notes

Routing belongs at the session-factory boundary (`RunnerAgentSessionFactory`), which
already receives the full `step`. The opencode-specific session becomes one adapter
among four. No changes to the runner loop or MCP handoff/finish contract are required
by this decision.
