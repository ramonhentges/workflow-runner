# ADR-006: Add `GET /workflows?cwd=` to list workflow files for a working directory

## Status

Accepted

## Date

2026-05-31

## Context

The Start-run flow lets the user pick a workflow from a cwd's `./workflows`
folder. A browser cannot read the local filesystem, and the daemon exposes no
endpoint to enumerate workflow files. `POST /runs` already accepts an absolute
`workflowPath` + `cwd`, but provides no discovery.

## Decision

Add a new daemon HTTP endpoint **`GET /workflows?cwd=<dir>`** that returns the
`*.json` workflow files found directly under `<cwd>/workflows`. The endpoint:

- requires `cwd` and resolves the `workflows` subdirectory beneath it;
- returns a list of entries `{ name, path }` where `path` is the absolute path
  suitable for `POST /runs`;
- returns an empty list when the folder is absent (not an error), and a 400 for
  a missing/invalid `cwd`;
- is registered like the other routes in `src/app/api/`, inheriting the same
  loopback Host allowlist and (via ADR-004) CORS.

It only lists files; it does not parse or validate workflow contents. Manual
path entry in the UI remains available as a fallback.

## Alternatives Considered

### Alternative 1: Manual path only (no endpoint)

- **Pros**: Zero backend change.
- **Cons**: Weaker start-run UX than the PRD describes; user must know paths.
- **Why rejected**: User chose to add the endpoint for the full UX.

### Alternative 2: Endpoint returns parsed step lists too

- **Pros**: Could power richer previews.
- **Cons**: Couples listing to workflow parsing/validation; broader surface.
- **Why rejected**: YAGNI; listing names/paths is enough for the picker.

## Consequences

### Positive

- Completes the PRD's start-run experience with a small, focused endpoint.
- Reuses existing routing, security, and OpenAPI machinery.

### Negative

- New endpoint to implement, test, and document (including `openapi.json`).

### Risks

- Path traversal / reading outside the intended folder. *Mitigation*: resolve
  strictly to `<cwd>/workflows`, list only direct `*.json` children, no
  recursion, loopback-only.

## Implementation Notes

New file `src/app/api/routes/workflows.ts` registered in `app.ts`; add a zod
response schema to `schema.ts` and cover it in the OpenAPI completeness test.
